## PaperPal

A chapter-wise practice hub for Manipal previous-year questions. Questions are
extracted from the PDFs in `papers/`, curated by subject/chapter, and served
through a small static web app. The paper archive browser is disabled for now.

The bank combines **220 curated questions** with automatically extracted question
blocks from the local PDF archive. Automatic imports are flagged in the app and
link back to the source paper because they do not have verified official solutions.

### Quick start

```sh
uv sync                  # install dependencies
uv run paperpal build    # validate data and index the local PDF archive
uv run paperpal serve    # open the app at http://127.0.0.1:8000/
```

Use `uv run paperpal serve --no-browser --port 8080` to run it without opening a browser
or on another port.

### CLI

| Command | What it does |
| --- | --- |
| `uv run paperpal build` | Validate `data/`, build the split question bank and its lazy-load index, and index local PDFs in `data/archive.json` |
| `uv run paperpal stats` | Print question counts by subject/chapter |
| `uv run paperpal extract` | Dump the text of every PDF in `papers/` to `build/extracted/` for review |
| `uv run paperpal images` | Extract embedded images from every PDF into `build/pdf-images/` for review |
| `uv run paperpal scrape` | Download all category papers from pyq.arzvak.com into `papers/` |
| `uv run paperpal serve` | Serve the app locally |

`build` is the gatekeeper: it rejects duplicate question IDs, unknown subjects,
chapters or papers, bad MCQ answer indexes, descriptive questions without a solution,
questions with no paper reference, and figure references whose files are missing or
outside `web/`. Run it after every data edit.

### Downloading papers

`paperpal scrape` pulls the full category catalogue from the public
`https://pyq.arzvak.com/api` endpoint and downloads each PDF from the site's mirror.
Papers land in a subject / year / exam layout:

```
papers/<subject-slug>/<year>/<regular|makeup>/<paper title>.pdf
```

Downloads are deduplicated by mirror URL and by SHA-1 against PDFs already in the
archive, and every run writes `papers/scraped-manifest.json` with the source URL,
size, hash and status of each paper. Reruns read that manifest and skip every paper
whose mirror URL was already downloaded (without requesting the file again), so the
command resumes an interrupted scrape and is cheap to run repeatedly. Pass
`--overwrite` to force a fresh download of everything.

```bash
uv run paperpal scrape --dry-run --limit 20   # preview paths
uv run paperpal scrape --semester "Semester 1" --workers 6
uv run paperpal scrape --overwrite            # re-download everything

# Resume an interrupted all-category scrape later (completed URLs are skipped)
scripts/resume_scrape.sh
```

`scripts/resume_scrape.sh` appends command output to `papers/scrape-run.log`.
Set `PAPERPAL_WORKERS` to adjust concurrency, or pass normal scrape options
such as `--limit` or `--dry-run`.

Use `--out` to write to a different directory.

### Project layout

```
index.html               generated entry page for the clean home URL (do not edit)
bank/index.html          generated entry page for /bank/ (do not edit)
practice/index.html      generated entry page for /practice/ (do not edit)
data/
  subjects.json          subject + chapter taxonomy (IDs used by questions)
  papers.json            paper metadata, PDF paths, solution/answer-script links
  questions/*.json       hand-curated question chunks, one or more files per subject
  bank.json              generated manifest for the split question bank
  bank-parts/*.json      generated question parts, each under 20 MB
  bank-index.json        small website index for lazy-loading subjects (generated)
  bank-subjects/*.json   generated question chunks loaded one subject at a time
  archive.json           generated index of every local PDF (do not edit by hand)
  auto-questions.json    generated raw question imports (do not edit by hand)
papers/                  source PDFs (question papers, solutions, answer scripts)
  scraped-manifest.json  generated by `paperpal scrape`
src/paperpal/
  build.py               validation, merging and statistics
  extract.py             PDF text and embedded-image extraction helpers
  scrape.py              pyq.arzvak.com catalogue fetch and PDF downloader
  serve.py               local static server (blocks dotfiles and listings)
build/
  extracted/             text dumps produced by `paperpal extract`
  pdf-images/            candidate images produced by `paperpal images`
web/
  index.html             app shell (source for the clean-URL entry pages)
  app.js                 filters, practice mode, bookmarks, subject search
  styles.css             responsive light/dark styling
  assets/figures/        curated diagrams referenced by the question bank
  vendor/katex/          bundled KaTeX (renderer + fonts, MIT licence)
```

The frontend is plain HTML/CSS/JS with no CDN dependencies. It fetches the small
`../data/bank-index.json` first and lazy-loads one subject chunk at a time, so it
must be opened through `paperpal serve` (or any static server rooted at the repo)
rather than as a `file://` URL.

GitHub Pages rejects individual files over 100 MB, so the full question bank is
written as a small `data/bank.json` manifest plus ordered parts in
`data/bank-parts/`. Each part is at most 20 MB; concatenate the `questions`
arrays from the listed `questionParts` to reconstruct the complete bank.

### GitHub Pages

The site is published from the repository root on the `main` branch:

- Home: <https://ksharizard.github.io/paperpal/>
- Question bank: <https://ksharizard.github.io/paperpal/bank/>
- Practice: <https://ksharizard.github.io/paperpal/practice/>

The app shell lives in `web/index.html`. `uv run paperpal build` generates the
root `index.html` and the `bank/` and `practice/` directory entry pages from it,
changing only the `<base>` so assets and data resolve correctly from every
route. GitHub Pages serves each directory's `index.html`, so refreshing a clean
URL works without server rewrites. GitHub Pages redirects `/paperpal/bank` to
`/paperpal/bank/`. Old `/web/` links and `#bank`-style hashes still load and are
rewritten to the clean URL in the browser.

PDFs are intentionally not committed for now (`papers/` is in `.gitignore`), and
the paper archive browser is disabled for now. The question bank and practice
mode work. To publish the PDFs later, update `.gitignore`, commit them, and keep
the published site under GitHub Pages' 1 GB limit. `data/auto-questions.json` is
also ignored because it is a large build cache and is not needed by the site.

### Maths / LaTeX

Question text, options, model answers and notes are rendered as rich text. Wrap maths
in any of the usual delimiters:

```text
Inline:  $E = mc^2$ or \(E = mc^2\)
Display: $$\int_0^1 x^2\,dx = \frac{1}{3}$$ or \[\int_0^1 x^2\,dx = \frac{1}{3}\]
```

KaTeX is bundled locally, so rendering works offline. Older plain-text notation is
also handled: `x^2`, `a_1`, `sqrt(2)`, `10^-3` and `->` are shown as typographic
superscripts, subscripts, radicals and arrows. For full LaTeX quality, use the
delimited form.

Automatic extraction goes through `src/paperpal/mathtext.py`. It reads Poppler's
XML text fragments, rebuilds superscripts/subscripts from their bounding boxes,
folds simple stacked fractions into `\frac`, detects small matrices, maps Adobe
Symbol glyphs, and wraps the resulting maths in `$...$` before the question bank
is built. Re-run `paperpal extract` and `paperpal build` to refresh existing text
dumps after changing those heuristics.

Matrix detection trusts bracket-delimited blocks and only converts bracket-less
blocks near a strong matrix word. A known limitation is a matrix whose entries
are stacked fractions (common in Markov transition matrices): the PDF text layer
splits numerators and denominators onto separate lines, so a few of those blocks
can come through truncated or merged. Those are text-layer limitations rather
than rendering errors; the extracted value can be corrected by hand if needed.

Scanned/image-only PDFs have no text layer; they still need OCR or manual
curation before their questions can be imported.

### Diagrams from the PDFs

Extract the embedded images for review:

```sh
uv run paperpal images
# optional: raise the size threshold to hide small icons and formula fragments
uv run paperpal images --min-width 120 --min-height 100
```

Candidates are written to `build/pdf-images/`, grouped by paper, with an
`index.json` recording the paper, page and pixel size. Identical images are written
once. Review the candidates, copy the genuine diagrams into `web/assets/figures/`,
and attach them to questions. Formula fragments, university crests and decorative
icons are deliberately not part of the curated figure set.

### Question format

Each file in `data/questions/` is a JSON array. A question looks like this:

```json
{
  "id": "bme-gt-02",
  "subject": "basic-mechanical",
  "chapter": "gear-trains",
  "topic": "Compound gear trains",
  "type": "DES",
  "marks": 6,
  "question": "A set of gear wheels is available ... Sketch an arrangement ...",
  "solution": "Mount the smallest gear as the driver ...",
  "images": [
    {
      "src": "assets/figures/gear-train-table.png",
      "alt": "Table of available gear wheels A to H",
      "caption": "Available gear wheels for the compound gear train.",
      "placement": "question"
    }
  ],
  "papers": [
    { "id": "bme-2024-jan", "qno": "Q2B" }
  ],
  "note": "The gear table is reproduced from the question paper."
}
```

- `type`: `MCQ` or `DES` (descriptive).
- `options` + `answer`: required for MCQ; `answer` is the zero-based index of the
  correct option.
- `images`: optional array of diagrams. `src` is relative to `web/`, and `placement`
  is `question` (shown with the question, the default) or `solution` (shown only after
  revealing the answer). `alt` and `caption` are optional but recommended.
- `papers`: every place the question appeared. Repeats are counted from this array,
  so merge duplicates into one question with multiple references.
- `note`: optional clarification about figures, marking variations, etc.

To add questions, create or edit a file in `data/questions/`, use chapter IDs from
`data/subjects.json` and paper IDs from `data/papers.json`, then run
`uv run paperpal build`.

### Frontend features

- Subject/chapter sidebar with per-chapter counts.
- Search across question text, topics, solutions, options and paper codes.
- Filters for type, year and bookmarks, plus shuffle.
- Reveal model answers, attempt MCQs inline, and bookmark questions (stored in
  `localStorage`).
- Answers are automatically split into sentence/step lines for readability; explicit
  newlines in a `solution` string are preserved.
- Diagrams appear with the relevant question or model answer and can be clicked for a
  full-size lightbox view.
- Practice mode: search and choose a subject/chapter, auto-score MCQs, review
  solutions.
- Light/dark theme toggle.

### Notes on the data

The original question bank is curated from extracted PDF text. The build also
imports numbered question blocks from downloaded papers automatically; these are
raw text imports, flagged in the UI, and should be verified against their source
PDFs before being treated as authoritative.
Genuine diagrams embedded in the source PDFs are extracted and attached to the
matching questions; any figure that could not be recovered is described in text or
called out in a `note`. Physics papers span the current applied-physics syllabus and
older engineering-physics papers, while basic-mechanical papers cover the
International Centre for Applied Sciences and MIT Manipal variants.
